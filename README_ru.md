## 1. Назначение приложения

Приложение строит безопасный морской маршрут между двумя точками и сравнивает его
с кратчайшим возможным маршрутом.

1. **Классификация зон.** Нейронная сеть (остаточный многослойный персептрон на
   PyTorch) относит каждую ячейку географической сетки к одной из четырёх зон:

   | Зона | Значение | Вес прохождения |
   |---|---|---|
   | `OPEN_SEA` | открытое море, глубокая вода вдали от берега | 1,0 |
   | `COASTAL_SEA` | прибрежное море, судоходная вода у берега | 1,8 |
   | `NEAR_COAST` | суша не далее 5 км от береговой линии | непроходима |
   | `COASTLINE` | суша вдали от моря | непроходима |

2. **Карта стоимости.** Зоны преобразуются в карту стоимости прохождения. Водные
   ячейки, граничащие с сушей, дополнительно штрафуются множителем 1,6, чтобы
   маршрут держался на безопасном расстоянии от берега.
3. **Поиск маршрута.** На одной карте стоимости доступны четыре метода поиска,
   основанные на одной и той же стоимости дискретного шага
   `c(u, v) = d_gc(u, v) · (w(u) + w(v)) / 2`:
   * **A\*** — точный метод с допустимой эвристикой по дуге большого круга (по умолчанию);
   * **алгоритм Дейкстры** — точный метод без эвристики (эталон для A\*);
   * **динамическое программирование** — точный метод: уравнение Беллмана
     `V(v) = min_u [c(v, u) + V(u)]`, `V(цель) = 0` решается итерацией по значениям,
     маршрут строится спуском по функции Беллмана от точки отправления;
   * **генетический алгоритм** — эволюционный поиск по последовательностям путевых
     точек под управлением функции приспособленности; результат сравнивается с
     точным оптимумом.
4. **Сравнение и экспорт.** Маршрут сравнивается с ортодромией (кратчайшим путём на
   сфере, который обычно пересекает сушу) и экспортируется в **GeoJSON, CSV и PDF**.
   Каждый маршрут сохраняется в базе данных **SQLite**.

Браузерный клиент показывает ход планирования **в реальном времени** через
WebSocket: построение сетки, прогресс классификации ячеек, число раскрытых
вершин A\*, итерации динамического программирования или номер поколения
генетического алгоритма.

## 2. Полученные результаты

Все приведённые ниже числа получены скриптами из папки `scripts/` и могут быть
воспроизведены (раздел 6).

**Набор данных.** Вторая редакция размеченного набора, предоставленная
руководителем, содержит 156 838 точек в одиннадцати морских районах; к первой
редакции добавлено 4 000 точек Эгейского моря (по 1 000 каждого класса).

**Очистка данных.** У 5 427 из 156 838 точек (3,46 %) класс противоречит
измеренной высоте или глубине — например, точка «прибрежное море» лежит на
несколько метров выше уровня моря. Проверяются оба измерения точки (`noaa_depth`
и `elevation`) с допуском ±5 м; противоречивые точки удаляются до обучения
(`src/maritime_route/data/cleaning.py`). Остаётся 151 411 точек — ровно столько,
сколько указано руководителем для этой редакции.

**Классификатор** (22 712 точек отложенной тестовой выборки очищенного набора):

| Показатель | Значение |
|---|---|
| Точность (accuracy) | **96,95 %** |
| Macro F1 / каппа Коэна / macro ROC-AUC | 0,9695 / 0,9582 / 0,9985 |
| Ошибки «вода ↔ суша» (критичные для безопасности) | 67 (0,29 %) |
| Параметры / обучение | 98 364 / 97 эпох, 4,3 мин на CPU |

Точность в каждом из одиннадцати морских районов записана в
`models/region_metrics.json`: от 93,5 % в Южно-Китайском море до 99,5 % в Красном
море; в добавленном Эгейском море — 97,9 %.

**Построение маршрутов** (6 рейсов в европейских водах + 11 рейсов, по одному в
каждом районе):

| Результат | Значение |
|---|---|
| Ортодромии, пересекающие сушу | 17 из 17 |
| Судоходные оптимизированные маршруты (по оценке классификатора) | 17 из 17 |
| A\*, Дейкстра и динамическое программирование | одинаковая оптимальная стоимость на всех 17 рейсах; A\* раскрывает в среднем в 2,5 раза меньше вершин, чем алгоритм Дейкстры |
| Генетический алгоритм | судоходный маршрут найден в 15 из 17 рейсов; в среднем на 1,1 % (районы) и 3,8 % (Европа) выше оптимума |
| Удлинение безопасного маршрута | в среднем +17 % (Европа) и +28 % (районы) |

**Тестирование на 100 случайных рейсах** (`scripts/route_audit.py`; каждый маршрут
проверяется через каждый километр по независимой маске суши с разрешением 1 км —
GLOBE / global-land-mask):

| Результат | Рейсов |
|---|---|
| Курс проложен правильно | 66 |
| Курс касается берега (участки суши короче 3 км) | 5 |
| Курс пересекает сушу | 19 — в 16 случаях классификатор принимает редко размеченную сушу за воду, в 3 — диагональный шаг сетки |
| Маршрут не найден | 10 — в 7 случаях нет открытого морского сообщения (Карибское море ↔ Тихий океан, Босфор), в 3 проход закрыт на классифицированной сетке |

Все рейсы перечислены в `docs/figures/route_audit.csv` и нанесены на карты в
приложении C пояснительной записки. Ошибки показывают, где набору данных не хватает
точек у побережья.

**Автоматическая проверка по береговой линии (версия 1.2).** Поскольку тест показал,
что классификатор иногда принимает редко размеченную сушу за воду, планировщик теперь
так же проверяет *каждый* маршрут (`src/maritime_route/routing/coast_check.py`): маршрут
через каждый километр сверяется с независимой маской суши; если он пересекает сушу на
3 км и более, соответствующие ячейки сетки блокируются и поиск повторяется (при
необходимости на более мелкой сетке), а маршрут, который всё ещё пересекает сушу,
выводится с красным предупреждением. Результат показывается плашкой над сводкой
маршрута, а также в PDF-отчёте, GeoJSON-экспорте и базе данных. Повтор теста на
100 рейсах с проверкой:

| Результат | Без проверки | С проверкой |
|---|---|---|
| Курс проложен правильно | 66 | 75 |
| Курс касается берега | 5 | 15 |
| Курс пересекает сушу | 19 | 0 |
| Маршрут не найден | 10 | 10 |

19 из 19 неправильных курсов исправляются автоматически;
правильные рейсы сохраняют свои маршруты, а среднее время запроса растёт примерно на 1 %.
Четыре из пяти предустановленных рейсов интерфейса без проверки также пересекали сушу
(Хельсинки → Копенгаген — на 108 км), теперь все они проходят проверку. Для проверки
нужен пакет `global-land-mask` (входит в `requirements.txt`); без него планировщик
работает как раньше.

Генетический алгоритм не справляется с рейсом Роттердам → Гданьск: он сходится к
проливу Эресунн, который сетка закрывает на одну ячейку, и не может перейти к
Большому Бельту, найденному A\*; и с рейсом Пирей → Салоники, где ни одна особь не
находит прохода между островами Эгейского моря без пересечения суши. Это
известная слабость эволюционного поиска в «лабиринтной» акватории; она
обсуждается в пояснительной записке.

Рейс по Эгейскому морю строится с шагом сетки 0,1° (кнопка предустановки выбирает
его автоматически): при шаге 0,25° по умолчанию диагональный шаг сетки срезает
Аттику, которая уже одной ячейки. На некоторых островах Эгейского моря (Кея,
Наксос, Скиатос) в наборе нет ни одной точки суши, поэтому классификатор относит
их к морю.

## Версия 1.3 — замечания руководителя

* **Параметры задаются в приложении, а не в коде.** Панель *Параметры алгоритма* (*Algorithm parameters*):
  максимальное число шагов (A\*, Дейкстра), вес эвристики (взвешенный A\*), число
  итераций (динамическое программирование), размер популяции, число поколений (эпох),
  ранняя остановка, турнир, вероятности скрещивания и мутации, элита, число точек,
  штраф за сушу и seed (генетический алгоритм), а также сетка и **ограничение времени**.
* **Таймер и кнопка «Стоп».** Во время поиска показывается время; **■ Stop** прерывает
  любой поиск за 0.22 с. Исходы: найден, нет пути, лимит шагов, лимит времени, остановлен.
* **Каждый результат сохраняется в JSON-файл** (и успешный, и неуспешный) в
  `outputs/results`; в имени — координаты точек, алгоритм, исход и время поиска; в
  файле — запрос, все параметры, время и **все точки** с координатами; полный путь к
  файлу выводится на экран.
* **Собственный маршрут и промежуточные точки:** A и B ставятся щелчком в любом месте,
  перетаскиваются или вводятся; **Shift + щелчок** добавляет промежуточную точку.
* **Сложные курсы:** адаптивная область поиска, объединение маски суши с картой
  стоимости, двухуровневый поиск в коридоре вокруг грубого маршрута.
* **Сравнение алгоритмов для одного курса** с прогрессом и остановкой, маршруты всех
  методов на карте и **оценка сложности** рядом с измеренной работой.
* **Интерфейс на английском, русском и китайском языках:** кнопки **EN / RU / 中文** в
  заголовке; выбор запоминается в браузере, результаты на экране перерисовываются на новом
  языке (`web/static/js/i18n.js`). Файлы результатов и отчёты остаются на английском.
* Эксперимент `scripts/complex_routes.py`; Dijkstra: 1,000 steps → step limit, 10,000 → route (6,728 steps needed); A* needs 5,351.

| Gdańsk → Bergen | касается берега, 5.7 s | касается берега, 1.5 s |
| Helsinki → Copenhagen | касается берега, 0.7 s | верно, 0.6 s |
| Rotterdam → Gdańsk | верно, 3.9 s | касается берега, 3.9 s |
| Piraeus → Rhodes | касается берега, 1.0 s | касается берега, 1.1 s |
| Jeddah → Dubai | нет маршрута, 126.4 s | верно, 5.5 s |

## 4. Установка и запуск

```bash
git clone https://github.com/EDXiaoM/MaritimeRouteAI.git
cd MaritimeRouteAI

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

python -m pip install --upgrade pip
pip install -r requirements.txt

python scripts/run_server.py
```

После сообщения `Zone classifier ready` откройте <http://127.0.0.1:8000>.
Обученная модель уже находится в папке `models/`, поэтому для запуска
приложения **обучение не требуется**. Подробная инструкция для каждой
операционной системы, в том числе установка CPU-версии PyTorch, приведена в
[docs/INSTALL.md](docs/INSTALL.md) и в руководстве пользователя
[docs/User_Guide_MaritimeRouteAI.pdf](docs/User_Guide_MaritimeRouteAI.pdf).

### Обновление до последней версии

Копия, полученная через `git clone`, обновляется на месте — остановите сервер
(**Ctrl + C**) и в папке проекта выполните:

```bash
git pull
pip install -r requirements.txt   # при активированном окружении .venv
python scripts/run_server.py
```

База данных, файлы результатов в `outputs/results` и окружение `.venv`
сохраняются. Копию, скачанную в виде ZIP-архива, нужно скачать заново
(подробнее — [docs/INSTALL.md](docs/INSTALL.md), раздел 2.5).

## 5. Работа с приложением

1. Дважды щёлкните по карте (сначала точка отправления, затем назначения),
   перетащите маркеры, введите координаты или нажмите **предустановку**
   (Kiel → Tallinn, Rotterdam → Lisbon, Helsinki → Copenhagen,
   Odesa → Novorossiysk, Piraeus → Thessaloniki).
2. Выберите **алгоритм поиска** (A\*, Дейкстра, генетический алгоритм,
   динамическое программирование или ортодромия), шаг сетки и скорость судна.
3. Нажмите **Build route** и следите за индикатором выполнения.
4. Результат показан в блоке *Route summary*; вкладка **Compare** содержит
   сравнение с ортодромией; кнопка **Compare algorithms** запускает все пять
   методов на одной карте стоимости.
5. Экспорт — кнопки **GeoJSON**, **CSV** и **PDF report**.
6. Собственный трек AIS загружается на вкладке **Data** (`.geojson`, `.csv`,
   `.json`); пример — `data/samples/sample_ais_track.geojson`.

Все элементы управления описаны в руководстве пользователя
([PDF](docs/User_Guide_MaritimeRouteAI.pdf), [Markdown](docs/USER_GUIDE.md)).

## 6. Воспроизведение результатов

Размеченный набор `merged.geojson` (119 МБ, вторая редакция с Эгейским морем)
слишком велик для хранения в самом репозитории; он приложен к
[релизу v1.0](https://github.com/EDXiaoM/MaritimeRouteAI/releases/tag/v1.0) как
`merged_geojson_v2.zip` (7 МБ). Скачайте архив, распакуйте файл в
`data/raw/merged.geojson` и выполните:

```bash
python scripts/prepare_dataset.py     # ~16 с: очистка, разбиение, признаки -> data/processed/
python scripts/train_model.py         # ~5 мин на CPU                       -> models/
python scripts/evaluate_regions.py    # точность по районам                 -> models/region_metrics.json
python scripts/benchmark_routing.py   # 6 европейских рейсов                -> docs/figures/routing_benchmark.json
python scripts/regional_examples.py   # 11 рейсов по районам + карта        -> docs/figures/regional_routes.json
python scripts/make_figures.py        # все рисунки записки                 -> docs/figures/
python scripts/route_audit.py         # 100 случайных рейсов, проверка суши -> docs/figures/route_audit.*  (нужен global-land-mask)
```

`prepare_dataset.py --no-clean` строит набор без очистки (для сравнения).

Каждый модуль, класс и функция снабжены строкой документации на английском языке
(назначение, параметры, возвращаемые значения); неочевидные места
прокомментированы в коде.

## 9. Ограничения

* Приложение — средство поддержки принятия решений, а не сертифицированная
  навигационная система; официальные электронные навигационные карты не
  используются.
* Модель стоимости не учитывает погоду, течения, приливы, лёд, системы
  разделения движения и осадку конкретного судна.
* Набор данных охватывает одиннадцать морских районов (Северная Европа, Эгейское
  море, Чёрное море и Восточное Средиземноморье, Красное море, Персидский залив и
  Аравийское море, Бенгальский залив, Малаккский пролив, Южно-Китайское море,
  Япония, Южная Африка, Центральная Америка). За их пределами классификация
  ненадёжна — например, море у Дурбана классифицируется как суша.
* Пролив уже одной ячейки сетки находится только после автоматического
  измельчения сетки, и лишь до шага 0,04°.
